- Schema: [`coverage-artifact-1.0.0.schema.json`](coverage-artifact-1.0.0.schema.json) — shared by provider and
  consumer producers. The consumer model is documented in its top-level `description`.
- Samples (generated by `scripts/consumer_coverage.py` from `scripts/tests/fixtures/consumer/`, kept in sync by tests):
  - `samples/consumer-coverage-artifact-sample-1.0.0.json` — checkout-web → product-api, with a spec, `locations: full`.
  - `samples/consumer-coverage-artifact-sample-no-spec-1.0.0.json` — mobile-app → loyalty-api, no spec, `locations: hashed`.
- `samples/provider-coverage-artifact-sample-1.0.0.json` — Drift's `one-of` coverage example (`Examples/coverage`) converted to 1.0.0 by

## Consumer model in one table

| Level | Items | Tested when |
|-------|-------|-------------|
| Operations | operations the code calls | ≥1 pact interaction matches method + path template |
| Responses | success + statuses the handling code checks | an interaction returns that status |
| Valid inputs | parameters, body fields, values the code sends | an interaction sends it (and that value) |
| Response fields | fields the code reads | an interaction for that status includes the field |
| Input → response | pact interactions | listed as evidence; no percentage |
| Invalid inputs | not measured | `totals.inputs.invalid` is `null` |

States: `tested`, `notTested`, `excluded` (with `excludedReason`). `failing`/`notTestedDirectly` are provider-only.
`percent = (tested + failing) / (total − excluded)`, one formula for both sides: a failing test still counts as covered, `notTested` and
`notTestedDirectly` stay in the denominator. For consumers `failing` is 0, so it equals `tested / (tested + notTested)`. Excluded and
unresolved are outside it; `null` when the denominator is 0.

Not percentages: `observations` (pact field the code never reads) and `unresolved` (calls/interactions that could not be
mapped; count in `totals.unresolved`).

Locations (`policy.locations`): `full` (file, line, symbol, commit, hash), `hashed` (commit + hash), `none` (no table, no refs).

## Changes from 0.4-draft

Semantic `schemaVersion`; `tests[]` tagged `type: drift|pact`; report-level `locations` table referenced by
`derivedFrom`, `nearestTests`, `tests[].location`; consumer additions (all optional): `responseField` level and
`totals.responseFields`, `totals.inputs.invalid: null`, `matchedBy`, `callSites`, `observations`, `unresolved`,
`totals.unresolved`, `source.repository`, `source.analysis`, policy `responses` / `excludeStatuses` / `locations`.

## Provider fields (merged from Drift's 0.4-draft)

One schema serves both sides. These are optional and mostly provider-only; `participant` and `source.commit` are optional so a
provider result can leave them to the publish.

| Field | Notes |
|-------|-------|
| `source.tool`, `source.generationMethod`, `source.coverageModelRef` | The rules in force (`namespace`, `spec`, `specHash`, `modelVersion`, `policy`) |
| `policy.maxDepth`, `maxFieldPairs`, `fieldLimits` | Model settings; `largeEnumLimit` already existed |
| item `kind`, `in`, `name`, `class`, `value`, `variant`, `parent`, `mediaType`, `status`, `occurrenceCount`, `generation` | Typed HTTP item fields (enums follow Drift) |
| `operations[].pairs`, `operations[].crossCoverage`, `crossCoverage` | Measured pairwise coverage (`strength: 2`) and input → response pairs |
| `operations[].notMeasured` | What the model does not measure (`depth`, `variantNegative`, …) |
| `operations[].totals` | Per-operation totals, same shape as `totals` |

Open decisions for the PM: the artifact carries states and percentages (Drift's agreed Q8 was evidence only, with states derived on read);
`participant`/`counterparty` are named `counterparty` here (Drift's schema still says `counterpart`).

## Extensibility and notes

- Extra fields are allowed at every level, and readers ignore fields they do not know, so a new field never blocks a publish.
- `notMeasured` exists per operation and at report level (for things not tied to one operation).
- Input → response has no percentage on either side (`totals.inputResponse.percent` is `null`). Providers list pairs in
  `operations[].pairs`; consumers list items with `level: inputResponse`.
- An excluded item keeps only `excludedReason`; Drift's optional waiver `by`/`at`/`source` are deliberately not carried.
- `policy` is required and repeats `source.coverageModelRef.policy`; `label` is required (Drift writes the item id).
